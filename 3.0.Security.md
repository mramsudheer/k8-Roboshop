**RBAC** 👈 (`Role-Based Access Control`) determines which user gets permission for which resources, similar to file permissions in Linux.<br>
Just as we use “chmod” in Linux to set permissions, we use RBAC in Kubernetes (K8s). <br>
However, in K8s, there are two different categories of permissions: `“Role”` and `“ClusterRole”`. <br>
A `“Role”` is applied only to a specific namespace, meaning it only governs permissions.<br>
A `“ClusterRole”`, on the other hand, is applied to the entire cluster, meaning it governs permissions across all nodes and namespaces. <br><br>
In K8s, roles and cluster roles are defined using two types of manifests, unlike in Linux where we use just “chmod” to define permissions for a file.<br><br>
In K8s:<br>
In a `“Role”`, we define what permissions (verbs) are applied to specific K8s resources (like secrets, deployments) or within a specific namespace.<br><br>
In a `“RoleBinding”`, we define to whom these permissions are applied—whether it’s an individual user, a group of users, or a service account.<br><br>
You can assign a RoleBinding to a group of users, and the entire group will inherit the permissions defined in the Role.<br>
To check permissions in K8s, you can use the command “ `kubectl auth can-i [verb] <resource_name>`”, which is similar to using “ls -l” in Linux to view the permissions applied to a file.<br>
